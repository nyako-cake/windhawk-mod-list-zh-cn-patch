Windhawk mod 列表汉化补丁 v1.0.27
================================

这个补丁做什么
--------------
给已安装的 Windhawk 1.7.3 界面加一层汉化，覆盖三处：
1. 主界面的 mod 卡片名称与描述；
2. mod 详情页里的长说明正文（README 那种大段英文）；
3. mod「设置」页里的开关标题与说明。
界面本身的按钮、菜单是 Windhawk 自带的中文，不需要补丁。

怎么用
------
1. 双击「一键安装.bat」。
2. 弹出 UAC 提示时点「是」（要写 Program Files，必须管理员权限）。
3. 装完关掉 Windhawk 窗口，再重新打开（托盘图标或开始菜单都行）。
4. 进主页看卡片、点「详情」「设置」，英文就会逐步变成中文。
5. 「关于」按钮正下方新增一个「汉化已开 + ⚙」控件（悬在标题栏下方、右对齐关于按钮）：
   点开关可随时关闭汉化（界面立刻恢复英文原文），点齿轮打开汉化设置。

开关与设置
----------
「关于」按钮正下方有一个与原生按钮同尺寸的悬浮控件（窗口缩放时会自动重新贴靠）：
- 点「汉化已开 / 汉化已关」这一块 = 总开关。关闭后界面文字立即还原成英文原文，
  已缓存的译文保留，再打开马上恢复中文，不会重新联网。
- 点右侧 ⚙ = 打开「汉化补丁设置」面板（仿原版设置页的深色卡片风格），可改：
  * 启用界面汉化（总开关）
  * 翻译长正文（详情页 README 那种大段说明）
  * 翻译设置项短标签（如 Make expandable 这类两个词的开关标题）
  * 中英双语：中文一行，下面是灰色小字的英文原文，如「动态任务栏透明」+「Dynamic Taskbar Transparency」
  * 翻译引擎：自动（Google → MyMemory）／仅 Google／仅 MyMemory
  * 清空本地译文缓存，并显示已缓存条数与内置词表条数
  改完点「保存」生效；设置存在 webview 的 localStorage 里，重开界面依然保留。

卸载
----
双击「一键卸载.bat」，点「是」，装前备份的两个文件会逐字节还原，不留痕迹。

汉化是怎么来的
--------------
- 内置词表：取自 Windhawk 官方 zh-CN 目录里的中文译名（108 条名称 + 113 条描述），
  再加 20 条人工校对译名，命中就直接替换，不发网络请求。
- 机翻兜底（v1.0.3 起改为 Google 优先、MyMemory 备用）：
  Google 免费翻译接口译质更稳、句子更通顺；不通或被限流时自动退回 MyMemory。
  译文缓存到本地，翻一次就够，不会反复请求。
  * 夹了行内代码（SetWindowPos 这类）的段落按整段翻；
    代价是这些行内代码会变回普通字体，换来的是整段通顺中文，不再中英夹杂。
- 【v1.0.10 修复】上一版整段翻译会重建段落里的子节点，导致 Windhawk（React）
  报 Failed to execute removeChild on Node 的整页错误。现在改为：只清空文字值、
  只隐藏段内的行内元素（code/b/a 等），节点一个都不删，React 重绘不会再崩。
- 【v1.0.11 修复】标题栏与设置面板三处调整：
  1) 标题栏那排原生按钮（主页 / 搜索 / 设置 / 关于）整体左移，给汉化开关腾出位置；
     汉化开关不再压住「关于」，也不再浮在它下面，而是和它同一行、紧贴其右侧。
  2) 之前截图里重复出现的第二个「汉化已开」控件已清掉，标题栏只保留一个。
  3) 汉化设置面板的「取消 / 保存」按钮条改成吸底：面板内容再长，滚动时按钮也
     始终贴在面板底部，不用滚回去点保存。
- 【v1.0.12 修复】上一版「把按钮行左移」认错了容器：它从「关于」一路往上找含 3 个以上按钮
  的父节点，最后取到的是最外层整页容器，右内边距加在了整页上，mod 列表跟着一起左移。
  现在只认最内层那排按钮（要求：按钮不超过 8 个、只有一行高、右缘与「关于」基本齐平），
  一旦往上一级就超出这个形状，直接放弃加内边距，宁可把开关退回「关于」下方也不动整页布局。
- 【v1.0.13 调整】开关的右缘改成按 **mod 卡片列表的右缘** 对齐（不再按按钮行右缘）。
  做法：用第一张卡片上的「详情 / 移除 / 安装」按钮往上找到卡片网格容器，取它的右边界当基线；
  按钮行再按这个基线精确左移，让「关于」右侧恰好空出开关的宽度。找不到卡片列表时
  （比如 mod 详情页、设置页），退回按按钮行右缘对齐，再不行就退回「关于」下方。
- 【v1.0.14 修复】v1.0.13 在真机上开关右缘仍越出列表约 90px，原因是两处探测在真实界面里都不成立：
  ① 卡片网格的子元素数量超过 12（mod 多时一行十几个格子）被过滤，回落到了外层容器；
  ② 标题栏那几个按钮的外层容器是整条工具栏（右缘在窗口最右边），与「关于」右缘差得太多被判定不合格，
  两个探测同时失效后就退到了「贴窗口右边」的兜底。现在：卡片网格按「每个子元素都是卡片」识别、
  容器高度 ≥100 排除工具栏；按钮排按「子元素全是按钮（或每个子元素里正好一个按钮）」识别，不再比对右缘距离。
  摆放也改成用 right 偏移定位，右缘直接落在列表右缘上，不再受控件宽度测量误差影响；
  right 偏移用不含滚动条的视口宽度计算，避免被滚动条多顶出去十几像素。
- 【v1.0.15 修复】mod 详情页的 README 列表项出现「粗体小标题是中文、后面整句还是英文」，
  且同一个页面里有的条目全中文、有的半英文（看起来像随机）。原因：整段翻译拼文本时取的是
  节点**当前值**，句首那个 <strong> 先被单独译成中文后，整段文本就变成「中文 + 英文」的混合物，
  与上一版记录的英文原文对不上，于是每次 React 重绘都会重新发起一次新的翻译请求，
  谁的请求先回来谁就赢——粗体先回来就卡在半英文。现在整段翻译一律用**原始英文**拼接，
  文本不再随翻译进度变化，译文命中后整段一次性落定。代价：这类列表项会整句变成中文，
  句首那个粗体小标题不再单独加粗（仍保留原文会藏起来，关掉汉化即可还原）。
- 【v1.0.16 新增】正在翻译提示：还有译文没回来时，右上角开关下面会出现一个蓝色小圆点 +
  「正在翻译… 余 N 条」，N 是排队 + 正在请求的条数；队列一空自动消失，不挡任何点击。
- 【v1.0.16 新增】译文替换延迟（毫秒）：设置面板「常规」里新增输入框，默认 0。
  0 表示译文一到就替换；填 300 就是再多等 300 毫秒再写进页面，用来压掉整屏文字突然跳动的观感。
  延迟期间原文保持可见，且不会因为页面重扫而重复发起请求（不会无限推迟）。
  注意：点「保存」或切换开关时的整页重绘是立即生效的，延迟只作用于新译文落笔这一下。
- 【v1.0.17 修复】打开 mod 的「源代码」页会看到「正在翻译」提示亮起、并真的发出一堆翻译请求。
  原因：扫描时先调用了 translate() 入队，之后才判断 blocked() 跳过，所以 <pre>/<code>、monaco
  这些本来不该碰的区域，代码每一行仍然被送去翻译（虽然结果不会写回页面，请求白花了）。
  现在跳过判断前置到翻译之前，被跳过的区域一条请求都不会发。
- 【v1.0.17 修复】同时把 Windhawk 的源码查看器整块纳入跳过：ModDetailsSource（语法高亮容器）、
  ModDetailsSourceDiff（差异视图）、SyntaxHighlighter / DiffWrapper / language-cpp 等类名一律不译。
  源代码页里只有版本下拉、复制按钮这类正常界面文字仍按需要翻译，代码本身保持原样。
- 【v1.0.18 新增】设置面板里多了一行「离线翻译包（预抓取译文）」，点右侧「下载离线包」会做四件事：
  1) 从 mods.windhawk.net 拉官方目录 en.json 和 zh-CN.json（当前 885 个 Mod，约 1700 条名称与简介）；
  2) 官方目录里已经有中文的条目（现在 98 条）直接抄下来，不再送去机翻；
  3) 其余条目逐条送去机翻，结果存进界面本地存储（localStorage），每 25 条落一次盘；
  4) 以后断网、或者翻译接口限流时，页面优先读这份本地译文，不再发请求。
  下过一次之后按钮会变成「更新离线包」，官方新上架的 Mod 再点一次就补全。
- 【v1.0.18 说明】下载过程刻意放慢：两条并行、每条之间停 120 毫秒，避免被 Google 当成刷接口。
  下载中会显示「正在预翻译… 已翻译 / 总数（已离线 N 条）」，随时可以再点按钮停下；
  如果显示「翻译接口限流，等 30 秒再试…」，说明当前网络暂时被限流，脚本会自动等 30 秒重试，
  最多等三次；三次都不行就停下，已经存下的条目照样能用，过一阵再点一次会接着往下补。
  全部翻完 1600 多条大约 10 分钟；存的是纯文本，只有几十 KB，不占硬盘。
  卸载时这份离线包也会随界面缓存一起清掉（补丁本身不往别处写文件）。
- 【v1.0.19 新增】搜索框可以直接打中文了，两个搜索页都生效（「搜索」页找在线 Mod、「已安装的 Mods」页筛本地 Mod）。
  做法：不动你输入框里的字，在查找这一层补一次「中文 → 英文原文」的反查——
  例如输入「窗口圆角」能筛出 Custom Window Corner Radius，输入「任务栏」能筛出所有名称/简介里带任务栏的 Mod。
  多个词用空格分隔，仍然要求每个词都至少命中名称或简介之一，和原版英文搜索的规则一致。
- 【v1.0.19 说明】中文搜索能搜到什么，取决于本地有多少译文：内置词表 + 在线翻译缓存 + 你下载过的离线包。
  把离线包下完（覆盖官方 885 个 Mod 的名称与简介）之后，中文搜索基本就是全量的；
  还没翻过的 Mod 用中文搜不到，可以先点一次「更新离线包」再搜，或者继续用英文名搜。
  卸载补丁后这层中文匹配随之消失，搜索回到原版只认英文的状态。
- 【v1.0.20 新增】设置面板的「离线翻译包」里多了一项「预翻译并发」：1-6，默认 2。
  说明一下「多线程」到底能省在哪：官方目录就两个文件（en.json / zh-CN.json，各约 740KB），
  这两份本来就是同时下载的，加起来一两秒，再并行也压不出时间。真正耗时的是后面约 1670 条
  逐条的机翻调用，所以把并发开在这一段——每个 worker 一条串行链，各自按间隔发请求。
  调高（3-4）能明显缩短总时长；6 在网络上顺畅时才有意义，更容易撞限流。被限流时脚本会自动
  暂停 30 秒重试，连续三次就停下并提示，不会一直空转。
- 【v1.0.20 优化】Google 接口一旦返回 429（本机网络上是常态），会被冷却 10 分钟，
  这段时间只走 MyMemory，不再每条都先打一次注定失败的 Google 请求——请求量直接砍半，
  进度条也走得更匀。冷却结束后再试，通了就自动切回 Google 优先。
- 【v1.0.20 建议】第一次下载保持默认 2 观察一会儿；若几十秒都没进展，再往上调到 3-4；
  已经下过一部分的，点同一个按钮就是「更新离线包」，只会补新增或缺漏的条目。
- 【v1.0.23 新增】打开顶栏开关（或在设置里点「保存」把汉化打开）时，会重新抓取一次翻译：
  清掉之前失败条目的冷却和翻译通道的冷却，把还没翻的英文重新发一遍请求。
  以前的逻辑是失败一次要等 60 秒、通道被限流还要等 90 秒，开关关了再打开也只能看到同一批英文。
- 【v1.0.23 新增】设置面板「缓存与词表」多了一个「重新抓取」按钮，
  开关本来就开着、只想把当前页面的漏翻补上时点它即可（和开关打开的动作用同一套逻辑）。
- 【v1.0.23 说明】重新抓取不会清掉已经译好的内容，也不会重翻缓存里的条目，只补还没翻的部分。
- 【v1.0.24 新增】微软翻译（Azure）通道：设置面板多了一段「微软翻译（Azure）」，
  填自己的订阅密钥（KEY1）和区域就行。免费层 F0 每月 200 万字符，日常汉化够用。
  界面里写了申请步骤：portal.azure.com → 搜索 Translator → 创建资源选 F0 → 「密钥和终结点」复制 KEY1 与位置。
  配好之后「自动」模式会先走微软，失败再退到 Google / MyMemory。
- 【v1.0.24 新增】百度翻译（开放平台）通道：填 APPID 和密钥即可，界面同样带申请引导
  （fanyi-api.baidu.com → 管理控制台 → 开发者中心 → 申请通用文本翻译）。
  百度接口不返回 CORS 头，补丁改成用 JSONP（<script>）取结果，所以安装脚本会额外把
  https://fanyi-api.baidu.com 加进页面的 script-src 白名单——这是唯一能让它在界面里直接用的方式。
  免费版 1 次/秒，并发高了会返回 54003，补丁会自动冷却并退到别的通道。
- 【v1.0.24 说明】两个通道都有「测试连接」按钮：填完先点它，返回一句中文就说明密钥能用，再点「保存」。
- 【v1.0.24 修复】同一段英文在译文回来之前，连续几次扫描会重复发请求（付费接口会重复计费），
  现在同一段文本在途期间只发一次。
- 【v1.0.24 说明】设置面板「翻译通道状态」这一行现在会显示「微软：已配置 / 百度：未配置」之类的状态，
  密钥失效（401/403、52003/54001）也会直接写在这里。
- 【v1.0.25 修复】百度免费版 QPS 只有 1 次/秒：两个请求挨得太近，第二个必回 54003。
  补丁原来把 54003 当普通失败，一冷却就是 90 秒，再叠加「仅百度」没有后备通道，整页就停住不翻了。
  现在百度通道改成串行排队，两次请求之间至少隔 1.1 秒；54003 只等 1.1 秒就重试，不再冻结 90 秒。
- 【v1.0.25 说明】只有填了 APPID 和密钥、且不在冷却期时，请求才会进这条队列；
  没配百度时不会占队列，所以「自动」模式里 Google / MyMemory 的速度不受影响。
- 【v1.0.25 说明】诊断行遇到限流会显示「百度：限流 54003」，这是正常排队，不是密钥坏了。
  余额不足（54004）、语言方向不支持（58001）才会长时间停用这条通道。
- 【v1.0.25 使用建议】百度免费版按 1 次/秒算，一页几百条要翻上一阵；
  想快就把引擎切回「自动」，百度只做微软之后的一级补充，两边错开跑。
- 【v1.0.26 变更】按你的要求，微软（Azure）与百度两条通道整条删掉了：
  设置面板里不再有「微软翻译（Azure）」「百度翻译（开放平台）」两栏，也不再有订阅密钥、APPID、密钥这些输入框；
  引擎档位从 5 档回到 3 档：自动 / 仅 Google（两个通道）/ 仅 MyMemory。
- 【v1.0.26 说明】删掉的不只是界面：MD5 签名、JSONP 取数、付费接口调用这些代码也一并移除了，
  补丁不再向 api.cognitive.microsofttranslator.com 或 fanyi-api.baidu.com 发任何请求。

  连百度加的 script-src 那条一起清，不再是只追加不删除。

  引擎统一回落到「自动」，localStorage 里残留的 msKey / msRegion / bdAppid / bdKey 会被清掉。
- 【v1.0.26 保留】「同一段文本在途只发一次请求」这条去重逻辑留下了——
  它对所有通道都有效，能省重复请求，不是专为付费接口加的。
- 【v1.0.26 现状】现在只有三条免密钥通道：clients5 → 旧 Google → MyMemory，
  外加离线翻译包兜底；界面回归从 103 项精简到 89 项（删掉的正是微软/百度那几项），现 89 项全过。

  连备选通道的补发请求也一样排队，不再一瞬间丢出几十个并发。
- 【v1.0.27 修复】撞到 429 不再只给那条通道记冷却：整条队列一起暂停，
  第一次 2 秒，连续的 429 逐次加长到最多 60 秒；只要成功一次就把暂停清零。
- 【v1.0.27 修复】失败的文本从「4 次就放弃」放宽到 9 次，等待逐次加长（60 秒起，最多 5 分钟），
  到期自动回来重试；限流窗口过去后这些段落会自己变中文，不用手动刷新。
- 【v1.0.27 说明】「正在翻译… 余 N 条」现在把还在等重试的条目也算进去，
  并写明「（接口限流，约 X 秒后重试）」，不会再在页面还有英文时把提示条收起来。
- 【v1.0.27 说明】免费接口的配额是硬上限：一页几百条仍然可能等上几分钟。
  想立刻补全就点设置面板里的「重新抓取」，它会清掉冷却重新排队。
- 【v1.0.22 修复】表格视图的表头（Name / Description / Author / Version / Status）、
  筛选面板里的「Installed」，以及详情页等处的界面固定文案，以前永远显示英文，
  因为这类一两个词的短串过不了「像不像英文」的判定，压根不会发给翻译。
  这一版单独加了一张界面词表（Name→名称、Description→描述、Author→作者、
  Version→版本、Status→状态、Installed→已安装、Details→详情、Remove→移除 等 30 多条），
  命中就直接换中文，不再依赖联网。
- 【v1.0.22 修复】详情页 README 里总有几段整段英文、同页别的段落却是中文，原因有两条：
  1) 翻译失败后旧逻辑直接把那条冷却 10 分钟，通道限流一过也没人再补扫，页面就一直停在英文；
  2) 两条文本同时翻译时，慢回来的那条会把译文写进另一条的缓存键（并发里的变量共用问题）。
  现在失败会退避重试最多 4 次（1.2 / 2.4 / 3.6 / 4.8 秒），通道限流冷却从 10 分钟降到 90 秒，
  冷却结束自动再扫一遍；并发也改成每条各持自己的文本，不会再串译文。
- 【v1.0.22 超时】单条请求超时从 8 秒放宽到 12 秒（挂代理时偶尔会慢到这个量级）。
- 【v1.0.22 诊断】设置面板「离线翻译包」下新增「翻译通道状态」一行：
  「成功 N 条 / 失败 M 次（最近一次：接口限流，xx 秒后自动重试 / HTTP 429 / 网络不通）」，
  截图一看就知道是限流还是网络问题。
- 【v1.0.21 修复】上一版在真实网络下会卡住，原因查到三条：
  1) MyMemory 的匿名日额度用完就开始全程 429；
  2) Google 的 translate_a/single 这个接口对你这条线路长期 429，重试也没用；
  3) 目录文件只抓一次，失败就直接终止整次下载，于是只看到「Failed to fetch」。
- 【v1.0.21 新通道】换成 Google 的另一条直连接口（clients5.google.com 的 Chrome 词典通道，
  一次一条）。实测本机现在可以稳定返回中文，长句（上百字符的简介）也能整段翻译。
  现在顺序是：新通道 → 旧 Google 通道 → MyMemory，逐级退让；
  某条通道一旦 429/403，就冷却 10 分钟不再尝试，后面自动走下一级。
- 【v1.0.21 更稳的下载】目录抓取失败会自动重试三次（间隔 1.5 秒、3 秒），
  失败原因也不再是英文的 Failed to fetch，而是「网络请求被拦截或网络不通 / 请求超时 / 服务器返回 500」。
  上次已经存下的 415 条不受影响，再点一次就是从第 416 条继续补。
- 【v1.0.21 并发】默认并发从 2 调到 3（新通道每次约 1 秒，3 路比较合手）。
  如果三个通道同时被限流，会直接提示「所有翻译通道都被限流」并停下，不会空转半小时；
  已经下载好的译文照常可用。
- 只翻「像人话」的英文：至少 2 个单词（两个词时第二个词须小写，避免把作者名、专有名词翻掉）、字母占比正常；纯标识符（add-virtual-folders-to-nav-top）、
  版本号、作者名、文件路径、URL 一律跳过；代码块和等宽字体区域不碰。
- 断网也能用，只是没收录的内容会保持英文。
- 设置页的分组标题、开关标题（如 Make expandable / Hide duplicates）也在汉化范围内；
- 打开「中英双语」后每条译文分成两行：上面中文，下面灰色小字是英文原文，适合对照术语；
  长正文会明显变长，觉得挤就在设置里把它关掉（或关掉「翻译长正文」）。
  按钮、页签这类窄地方会自动退回单行「中文（英文）」的写法，避免把按钮撑高。
  This PC、Desktop 这类专有名词走内置词表，不走机翻。

关于换用微软翻译（v1.0.3 实测结论）
----------------------------------
- 微软官方 Translator（Azure）接口可以直连，webview 跨域也放行，
  但它必须携带订阅密钥（Ocp-Apim-Subscription-Key），免费 F0 层每月 200 万字符。
  要走这条路需要你先在 Azure 上开一个翻译资源拿到密钥。
- Edge 浏览器自带的那个免密钥通道（edge.microsoft.com/translate/auth 取 JWT）
  实测已返回 404，没有可用令牌，免费白嫖的路径已经失效。
- 所以本版用 Google 免费接口顶上，效果最接近浏览器整页翻译；后续你要是愿意开 Azure 密钥，
  可以直接把密钥填进脚本顶部的 AZURE_KEY 常量（同时把 translateOne 的第一顺位换成 azure），
  再双击一次安装即可。

注意事项
--------
- Windhawk 升级会覆盖 UI 目录，升级后需要重新双击一次「一键安装.bat」。
- 机翻结果偶尔不够地道，属正常；正文字数多时首次打开会等几秒逐步出中文。
- Google 免费接口在国内偶有抖动，失败会自动换 MyMemory，不会卡住界面。
- 卸载脚本依赖安装时生成的 _zh_backup 备份目录，别手动删除它。
